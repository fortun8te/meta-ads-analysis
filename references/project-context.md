# Project context

Load only the existing project material needed for the decision: current brief, verified product/offer facts, audience/customer evidence, accepted assets, prior decisions and later outcomes. No brand knowledge is bundled.

Keep each source's author, date, scope and evidence type. Separate official product facts, website claims, customer statements, user preferences, practitioner advice, assistant interpretations and research hypotheses. Current instructions control the requested scope; historical material supplies evidence, not execution permission.

For customer evidence, preserve source wording, thread/question context, sampling and freshness limits. A small comment sample is not prevalence. For regulated or comparative claims, seek the relevant substantiation; generic ingredient research or a competitor claim does not establish finished-product efficacy. Check current platform rules before finalizing publication copy when that is part of the authorized task.

Inspect the actual approved product/reference assets before discussing packaging or proposing production changes. A historical label of “winner” needs matching results; approval and measured performance are different states.

Reuse the existing project knowledge bank or ledger. Do not create a second brand database, copy private documents into this skill, or start collectors/schedules merely to fill context. Keep account/customer data and course materials outside public repositories. See [research and learning](research-and-learning.md) for attribution and reuse.
